## 1. 项目信息

| 项 | 内容 |
|---|---|
| Language | 简体中文 |
| 目标平台 | iOS only（不做 Android） |
| 技术栈 | Swift 5.9+ / SwiftUI / WidgetKit / App Group |
| 数据源 | Open-Meteo（免密钥公开 API），单一数据源 |
| 工程名 | `zhisheng_weather_ios` |
| 构建环境 | Windows 开发机 + GitHub Actions `macos-14` runner（`xcodebuild`） |
| 分发方式 | 自用，不上架 App Store（未签名 IPA / 自签 sideload） |
| 参考项目 | https://github.com/zhishengplus/ZhishengWeather（仅作能力对照，非代码移植） |

### 原始需求复述

将 Android 天气 App「枳生天气」以 **Swift/SwiftUI 全新工程**重写为 iOS 版，保留其核心气质（磷光终端风、无广告无账号、简洁专注），并**必须提供 WidgetKit 桌面小组件**。主 App 与小组件通过 **App Group** 共享天气数据。第一里程碑只交付**最小可用闭环**：Open-Meteo 取数 → 主屏展示 → 写入共享容器 → 小组件只读展示 → CI 出包。其余能力（多数据源、雷达、台风、地图、生活指数、多语言、完整城市管理）一律降级至 P1/P2 或明确排除。

### 已锁定的硬约束（前提，不再讨论）

1. 仅 iOS，Swift + SwiftUI（Objective-C 已排除，WidgetKit 只能用 SwiftUI）。
2. 必须有 WidgetKit 桌面小组件（用户核心诉求）。
3. 主 App ↔ 小组件数据共享**必须走 App Group**。
4. 本地是 Windows，无法编译 iOS；**编译/打包走 GitHub Actions macOS runner**。
5. 自用分发，不上架 App Store。

## 2. 产品目标

**一句话目标**：做一个能装在自己 iPhone 上、抬手看到天气、桌面小组件一瞥即知、干净无广告的天气 App。

**三个正交目标**

| # | 目标 | 衡量方式 |
|---|---|---|
| G1 | **数据可用**：单数据源稳定取到「当前天气 + 逐小时预报」，并可靠落入共享容器 | 冷启动到主屏出数据 < 3s（有网）；无网时有降级内容 |
| G2 | **一眼可读**：主屏与小组件在 0 交互下传达「温度 / 现象 / 体感 / 风湿 / 数小时趋势 / 月相」 | 主屏信息一屏内完成；Small 组件不滚动即可读全 |
| G3 | **可持续构建**：Windows 上也能通过 CI 稳定产出可安装 IPA | GitHub Actions 手动触发一次即出 IPA artifact |

## 3. 用户故事

| ID | 用户故事 | 关联目标 |
|---|---|---|
| US-1 | **As a** 每天出门前看天的用户，**I want** 打开 App 立刻看到当前温度、天气现象、体感温度、风速风向和湿度，**so that** 我能马上决定穿什么、带不带伞 | G2 |
| US-2 | **As a** 关心未来几小时变化的用户，**I want** 在主屏看到「现在 + 未来数小时」的温度与天气图标趋势，**so that** 我知道下午会不会转凉/下雨 | G2 |
| US-3 | **As a** 对天文小细节感兴趣的用户，**I want** 在主屏看到今天的月相与照亮比例，**so that** 我能了解当晚月亮状态 | G2 |
| US-4 | **As a** 不想每次开 App 的用户，**I want** 桌面 Small 小组件直接显示当前温度 + 天气图标，**so that** 解锁手机或扫一眼桌面就知道天气 | G2 / G1 |
| US-5 | **As a** 想多看一点趋势的用户，**I want** Medium 小组件在温度之外再多显示未来几小时，**so that** 不用打开 App 也能判断趋势 | G2 |
| US-6 | **As a** 早出晚归的用户，**I want** 小组件的数据与主 App 自动保持一致、且显示更新时间，**so that** 我不会被过期数据误导 | G1 |
| US-7 | **As a** 会断网/信号差的用户，**I want** 拉取失败时看到上一次的缓存数据与「更新于 xx:xx」提示，**so that** 界面不会白屏报错 | G1 |
| US-8 | **As a** 自用开发者，**I want** 代码推到 GitHub 后由 Actions 自动产出 IPA，**so that** 我在 Windows 上也能拿到可安装包 | G3 |

## 4. 需求池

> 优先级定义：**P0 = MVP 必须**（第一里程碑交付）；**P1 = Should have**（第二里程碑）；**P2 = Nice to have**。
> 每条含可验证的验收标准（AC）。

### 4.1 P0 — MVP 必须（共 10 条）

| ID | 需求 | 优先级 | 验收标准（AC） |
|---|---|---|---|
| **P0-1** 定位与坐标解析 | 获取用于查询天气的经纬度 | P0 | ① 首次启动请求 CoreLocation「使用期间」授权；② 授权成功 → 用真实坐标查询；③ 拒绝/失败/超时 → 回落到默认坐标（北京 39.9042, 116.4074）并在 UI 标注城市名；④ 全程无崩溃、无死循环弹窗 |
| **P0-2** Open-Meteo 数据接入与解析 | 单次请求拿到当前天气 + 逐小时预报 | P0 | ① 调用 `api.open-meteo.com/v1/forecast`，参数含 `current`、`hourly`、`timezone=auto`；② 用 `Codable` 解析为强类型 `WeatherSnapshot`；③ 字段覆盖：温度、体感、天气码、风速、风向、湿度、逐小时时段；④ 网络/解析错误返回 `Result`，不 crash |
| **P0-3** 天气码 → 图标/中文现象映射 | 将 Open-Meteo WMO code 映射为图标与文案 | P0 | ① 覆盖 WMO 0–99 全部常用码；② 每个码映射到 SF Symbol + 中文现象名（如 0→晴、3→阴、61→小雨、95→雷阵雨）；③ 未知码有兜底（问号图标 + "未知"） |
| **P0-4** 月相计算 | 本地纯算法计算月相，不依赖网络 | P0 | ① 输入日期 → 输出月相名称（朔/娥眉月/上弦/盈凸/满月/亏凸/下弦/残月）+ 照亮比例 0–100%；② 与参考值（已知满月日期）误差 ≤ 1 天；③ 纯函数，有单元测试 |
| **P0-5** 天气主屏 UI | SwiftUI 一屏呈现核心信息 | P0 | ① 含区块：城市/日期时间、超大温度、天气图标+现象、体感+高低温、风速风向、湿度、逐小时横向列表、月相；② 支持下拉刷新；③ 深浅色模式均不出现文字不可读；④ iPhone SE（375pt 宽）无横向滚动溢出 |
| **P0-6** 逐小时预报组件 | 横向展示「现在 + 未来 N 小时」 | P0 | ① 默认展示未来 12 小时；② 每小时显示 时间/图标/温度；③ 首项为「现在」；④ 横向可滚动且不遮挡主屏其他内容 |
| **P0-7** App Group 共享数据层 | 主 App 写、小组件读 | P0 | ① App Group ID 在 App 与 Widget target 的 entitlements 中一致；② 主 App 每次成功取数后写入共享容器（`UserDefaults(suiteName:)` 存 JSON）；③ 写入内容含 `snapshot` + `updatedAt` 时间戳；④ 小组件仅读不写 |
| **P0-8** WidgetKit Small 小组件 | 153×153 展示当前温度 + 图标 | P0 | ① 显示天气图标 + 温度（大字）+ 城市名 + 现象；② 无数据时显示占位（"—" / 图标 + "暂无数据"），不空白不崩溃；③ 采用 `.containerBackground` 适配 iOS 17；④ 三种渲染模式（全彩/单色/着色）均可读 |
| **P0-9** WidgetKit Medium 小组件 | 338×153 在 Small 基础上加逐小时 | P0 | ① 左侧保留温度+图标+城市，右侧横向展示未来 4–6 小时；② 与 Small 共用同一份共享数据；③ 布局在 iPad/横屏不被裁切（超出部分截断而非溢出） |
| **P0-10** 刷新与降级策略 | 定义何时取数、失败怎么办 | P0 | ① 主 App 冷启动 + 回到前台时刷新；② 主 App 刷新成功后调用 `WidgetCenter.shared.reloadAllTimelines()`；③ 小组件 Timeline 每个条目间隔 30–60 分钟，请求失败时保留旧数据并标注更新时间；④ 请求失败时主屏显示最后一次缓存数据 + "更新于 HH:mm" |
| **P0-11** GitHub Actions 构建出 IPA | Windows 上也能拿到安装包 | P0 | ① 工作流跑在 `macos-14`；② 支持 `workflow_dispatch` 手动触发；③ 通过 `xcodebuild archive` + `exportArchive` 产出 `.ipa`；④ 产物以 artifact 上传可下载；⑤ 构建失败时日志可定位到具体步骤 |

> **P0 条目数：11 条**（含 P0-1 ~ P0-11）。

## 5. UI 线框（文字描述）

### 5.1 主屏（SwiftUI，竖屏单列滚动）

层级由上至下，单一 `ScrollView` + `VStack`：

```
┌──────────────────────────────┐  ← ① 顶部栏（HStack）
│  北京                    ⟳   │     左：城市名（17pt Semibold）
│  9月11日 00:31               │     右：刷新按钮/下拉刷新手势
├──────────────────────────────┤  ← ② Hero 温度区（居中 VStack，最高层级）
│                              │
│           23°                │     超大温度 72–80pt Bold，视觉焦点
│                              │
│        ⛅  多云转晴           │     天气图标 40pt + 现象文案 20pt
│                              │
│     体感 21°   ↑22°  ↓15°     │     一行次级指标，14pt，弱化色
│                              │
├──────────────────────────────┤  ← ③ 指标格（2 列 LazyVGrid）
│   [ 💨 风速 ]  │  [ 💧 湿度 ] │     每格：图标 + 数值 + 单位/文字
│   3.2 m/s 东南 │    58%       │     风速含风向（如「东南风 3.2 m/s」）
├──────────────────────────────┤  ← ④ 逐小时预报（横向 ScrollView）
│  未来数小时                   │     区块标题 15pt
│  ┌────┬────┬────┬────┬────┐  │
│  │现在│ 1时│ 2时│ 3时│ 4时│… │     每列：时间 / 图标 / 温度
│  │ 23°│ 22°│ 22°│ 21°│ 21°│  │     列宽约 56pt，可横滑
│  │ ⛅ │ 🌙 │ 🌙 │ ☁️ │ ☁️ │  │
│  └────┴────┴────┴────┴────┘  │
├──────────────────────────────┤  ← ⑤ 月相区（HStack）
│  🌔  盈凸月        照亮 87%   │     左：月相图标；右：名称 + 照亮比例
├──────────────────────────────┤
│  更新于 00:31（缓存时高亮）   │  ← ⑥ 页脚：更新时间戳，12pt 弱化色
└──────────────────────────────┘
```

**层级与视觉说明**

- 视觉权重：② Hero 温度 > ④ 逐小时 ≈ ③ 指标格 > ① 顶部栏 > ⑤ 月相 > ⑥ 页脚。
- 配色：MVP 采用深色底 + 荧光绿/青色强调色（承接原项目磷光终端风）；复杂动效不在 MVP。
- 状态：加载中显示骨架占位；失败显示缓存 + 页脚时间戳；无缓存显示空态文案。

### 5.2 Small 小组件（约 153×153 pt）

```
┌────────────────┐
│ 北京           │  ← 城市名，12pt，左上角，次要色
│                │
│        ⛅      │  ← 天气图标 ~28pt，偏右/居中
│   23°          │  ← 温度 ~44pt Bold，视觉主体
│                │
│ 多云转晴       │  ← 现象文案 11pt
│        00:31   │  ← 更新时间，10pt，右下角，最弱
└────────────────┘
```

- 布局：`VStack` 三段（城市 / 温度+图标 / 现象），更新时间靠右对齐贴底。
- 优先级：温度 > 图标 > 城市 > 现象 > 时间；空间不足时先裁「现象」，再裁「时间」。
- 空态：温度位显示 `--°`，图标位显示占位符号，文案「暂无数据」。

### 5.3 Medium 小组件（约 338×153 pt）

```
┌────────────────────────────────────────────────┐
│ 北京                                   00:31   │  ← 顶部：城市 + 更新时间
├──────────────────────┬─────────────────────────┤
│                      │  现在  1时  2时  3时  4时│
│      ⛅              │   ⛅    🌙    🌙    ☁️    ☁️│
│   23°  多云转晴       │  23°   22°   22°   21°  21°│
│   体感 21°           │                          │
└──────────────────────┴─────────────────────────┘
   ← 左栏 ~40% 宽        右栏 ~60% 宽（横向趋势）
```

- 左栏沿用 Small 的「温度 + 图标 + 现象 + 体感」；右栏为未来 4–6 小时迷你趋势。
- 左右用极细分隔线或留白分区，不加重边框（保持干净）。
- 空间不足时右栏优先递减小时数（6 → 4 → 3），先保住左栏主体。

| Q1 | Bundle ID / App Group ID / App 显示名如何命名？ | 直接影响证书配置、entitlements、Actions secrets、小组件容器连通性；一旦开工后改名成本高 | `com.zhisheng.weather` / `group.com.zhisheng.weather` / 显示名「枳生天气」 |

| Q4 | 风速单位用 m/s 还是 km/h？温度是否支持 ℉？ | 影响数据展示与后续设置项设计 | 温度 ℃、风速 m/s（与原项目口径一致）；单位切换列 P1-7 |

| Q8 | 磷光终端风的视觉还原程度？ | 影响 MVP 设计工程量 | MVP 只做深色 + 荧光强调色的基础配色，动效列 P2-4 |
