## 3. 推荐方案：中央气象台台风网

### 3.1 为什么选它

1. **免 Key 且零鉴权**——实测无 UA（curl 默认 UA）、无 Referer、自定义 App UA 三种情况均返回 200，字节数完全一致（2797B）。这是最适合自用 App 的形态。
2. **有中文名**——这是国内用户看的核心信息（「摩羯」「诺洛」）。实测列表直接返回中文名，且连命名含义都有（诺洛的命名含义字段为 `null`，彩云为「天上的云彩」）。
3. **数据最全**——不只给实况路径点，还带**官方中央气象台（BABJ）的预报路径**（12/24/36/48/60/72/96/120 小时 8 个时效），以及七级风圈/暴风圈半径。这比 JMA 只给路径点更接近竞品体验。
4. **历史可回溯**——实测 `list_1950` 到 `list_2026` 全部 200，每年一个端点。
5. **HTTPS 可用**——实测 `https://typhoon.nmc.cn/...` 与 HTTP 返回完全一致的 200/12478B。iOS ATS 无需例外配置。

### 3.2 完整 URL 形态（实测可用）

```
# 1) 当前/默认台风列表（含中文名）
http://typhoon.nmc.cn/weatherservice/typhoon/jsons/list_default

# 2) 指定年份的台风列表
http://typhoon.nmc.cn/weatherservice/typhoon/jsons/list_2024

# 3) 单个台风的完整路径 + 预报（typhoonId 来自列表第 0 项）
http://typhoon.nmc.cn/weatherservice/typhoon/jsons/view_3346168
```

HTTPS 版本（三者均实测 200）：
```
https://typhoon.nmc.cn/weatherservice/typhoon/jsons/list_default
```

### 3.3 响应格式：JSONP 双层括号（重要坑）

响应**不是纯 JSON**，是 JSONP 包裹，且**括号嵌套两层**：

```
typhoon_jsons_list_default(({"typhoonList":[...]}))
                ^^^^^^^^^^^^^^    ^^                ^^
                回调函数名         外层括号          内层括号
```

实测 `list_default` 用 `json.loads` 直接解析会抛 `JSONDecodeError: Expecting value: line 1 column 1 (char 0)`。

**解码器必须做**：定位第一个 `(` 之后、最后一个 `)` 之前的内容；若得到的是 `({...})` 仍不是合法 JSON，需要再剥一层。最稳的做法是：先去掉回调函数名（到第一个 `(`），去掉尾部 `)`，若剩余串以 `(` 开头且以 `)` 结尾则再剥一层。

### 3.4 逐字字段名

#### 端点 1：`list_default` / `list_YYYY`

顶层：`{"typhoonList": [ ... ]}`，每项是**定长 8 元素数组**（实测 1950–2026 全部一致）：

| 索引 | 含义 | 实测样例 |
|---|---|---|
| 0 | `typhoonId`（数字，字符串拼接进 URL） | `3346168` |
| 1 | 英文名（大写；无名台风为 `"nameless"`；早年有 `(nameless)`） | `"NOLO"` |
| 2 | **中文名**（无名台风为 `"热带低压"`；实测存在末尾带换行符的值，如 `"小熊\n"`） | `"诺洛"` |
| 3 | 编号（数字或字符串，年份差异会导致类型不同） | `2628` / `"2426"` |
| 4 | 编号（重复字段） | `2628` |
| 5 | 内部序号，可能为 `null` | `null` |
| 6 | 命名含义（可能为 `null`） | `"天上的云彩"` |
| 7 | 状态：`"start"`（进行中）/ `"stop"`（已停止） | `"start"` |

**解码注意**：索引 3/4 的类型不稳定（2026 年是数字 `2628`，2024 年是字符串 `"2426"`），索引 2 需 `trimmingCharacters(in: .whitespacesAndNewlines)`。这两点都是实测踩到的。

#### 端点 3：`view_<typhoonId>`

顶层：`{"typhoon": [...]}`

**台风头部**（`typhoon[0...7]`，与列表端点同构）：
```
[3346168, "NOLO", "诺洛", 2628, 2628, null, null, "start", [ ...路径点... ]]
  0        1        2       3    4     5      6       7         8
```

**路径点** `typhoon[8]`：每个点是**定长 13 元素数组**（实测 8 个 2026 台风 + 3 个历史台风，arity 全为 13）：

| 索引 | 含义 | 实测样例 |
|---|---|---|
| 0 | 该点自身的 pointId | `3346169` |
| 1 | 时间，UTC，`yyyyMMddHHmm` **字符串** | `"202610050000"` |
| 2 | 时间，Unix 毫秒时间戳（数字） | `1791158400000` |
| 3 | 强度等级（英文缩写，见枚举） | `"SuperTY"` |
| 4 | 经度（**注意在前**，0-360 或 -180~180 混用，实测有 `179.4` 与 `179.4`） | `179.4` |
| 5 | 纬度（在后） | `24.8` |
| 6 | 中心气压 hPa（数字） | `935` |
| 7 | 最大风速 m/s（数字） | `52` |
| 8 | 移动方向（16 方位英文缩写，或 `"no"` 表示停滞） | `"W"` |
| 9 | 移动速度 km/h（数字） | `28` |
| 10 | 风圈信息数组，元素为 `["30KTS", 北, 东北, 东, 南, pointId]`（半径 km） | `[["30KTS",500,450,450,500,3346169], ...]` |
| 11 | **预报字典**，key 为预报机构（实测仅 `"BABJ"` = 中央气象台）。值是数组，元素为 `[leadHours, 起报时间, 经度, 纬度, 气压, 风速, 机构, 强度]`。历史台风/末段可能为 `null` | `{"BABJ":[[12,"202610050000",176.1,25.2,945,48,"BABJ","STY"], ...]}` |
| 12 | 时效信息数组，元素为 `[UTC时间, 北京时间字符串, null, null]`；历史台风可为 `null` | `["202610050000","2026年10月05日08时00分",null,null]` |

**预报时效实测**（诺洛首个路径点）：`[12, 24, 36, 48, 60, 72, 96, 120]` 共 8 个，强度随路径递减 `STY→STY→TY→TY→TY→TY→STS→STS`。

**强度枚举（实测收集全集，来自 8 个不同强度台风）**：
`TD`（热带低压）、`TS`（热带风暴）、`STS`（强热带风暴）、`TY`（台风）、`STY`（强台风）、`SuperTY`（超强台风）。索引 11 预报里的强度用同一套枚举。

**移动方向枚举（实测收集全集）**：
`N, NNE, NE, ENE, E, ESE, SE, SSE, S, SSW, SW, WSW, W, WNW, NW, NNW`，外加两个特殊值：`"no"`（停滞，老台风常见）和 `"0"`（实测在彩云的路径点中出现过）。

### 3.6 Referer / 频率限制 / 其他实测结论

| 项 | 实测结论 |
|---|---|
| 需要 Referer？ | **不需要**。实测不带 Referer 直接 200 |
| 需要特定 UA？ | **不需要**。实测 curl 默认 UA / iPhone Safari UA / 自定义 `ZhishengWeather/1.0 CFNetwork` / 空 UA 四种，全部 200 且字节数一致（2797B） |
| 频率限制 | **实测未观察到**。`view_3346168` 连打 12 次全部 `200/12478`，`list_default` 连打 8 次全部 `200/2797`，无一失败 |
| 错误 id 行为 | `view_9999999` 返回 **404 + HTML 错误页**（非 JSON）。解码器需容忍非 JSON 响应 |
| 数据时效 | 实测末点时间为 `202610070600` UTC = 北京时间 14:00，而实测请求时刻约为北京时间 17:00，**延迟约 3 小时**。符合官方 6h/3h 发布节律，非故障 |
| HTTPS | **可用**，实测 200 且字节数与 HTTP 完全一致 |
| 响应压缩 | 实测**不带** `--compressed` 也能拿到明文 2797B（`xxd` 首字节为 `74 79 70 68`，即 `typh`），说明服务端不强依赖 gzip。但**仍建议统一带 `--compressed`**（项目纪律，也省流量） |

### 3.7 建议的接入策略

1. **列表端点做「发现」**：`list_default` 拉全部（含已停止），过滤 `typhoon[7] == "start"` 得到当前活跃台风。国内用户默认只看活跃台风，条件满足时（如需历史路径）再按年份查 `list_YYYY`。
2. **台风详情端点做「路径 + 预报」**：`view_<id>` 一次拿全，**不要逐点再请求**。
3. **时间处理**：索引 1（UTC 字符串）与索引 2（Unix 毫秒）二选一，推荐用索引 2 免去时区解析坑；索引 12 的北京时间字符串可仅用于「发布时间」展示。
4. **JSONP 剥壳**：见 3.3，双层括号必须处理。
5. **缓存节律**：数据本身 3 小时量级延迟，建议缓存 30–60 分钟即可，不必高频轮询（实测无限流，但没必要）。
6. **风险提示（诚实说明）**：这是中央气象台的**网页前端数据接口**，非对外承诺的开放 API，理论上可能变更。缓解措施：解码器对索引位置做**容错映射**（如按类型而非固定下标取值），一旦结构变化能降级为部分可用而非崩溃。**该风险无法通过实测消除，只能缓解。**

## 4. 备选源：JMA（日本气象厅）

同样免 Key、同样实测可用，可作为西北太平洋的**第二数据源**（交叉校验或海外用户）。

**实测可用的 URL**：
```
# 活跃热带气旋列表
https://www.jma.go.jp/bosai/typhoon/data/targetTc.json

# 单个气旋的强度规格（含最大风速、气压、移动方向速度）
https://www.jma.go.jp/bosai/typhoon/data/TC2635/specifications.json

# 单个气旋的路径与预报（含概率圆）
https://www.jma.go.jp/bosai/typhoon/data/TC2635/forecast.json
```

实测响应（`targetTc.json`，315 字节）：

**JMA 关键限制（实测）**：
- **没有中文名**，只有 `name.jp`（如 `"ノロ"`）和 `name.en`（如 `"Nolo"`）。国内用户看到的「诺洛」必须靠 NMC 或本地映射表。
- 数值字段是**字符串**（如 `"pressure":"975"`、`"m/s":"35"`），解码需转数字。
- `pressureCircle` 提供概率圆半径，这是 NMC 没有的信息（NMC 只有风圈）。
- 实测 `map.json`、`TC2635/` 目录、`TC2635/map.png` 均 404——**没有底图瓦片**，路径渲染需自备底图（与本项目已接的 Open-Meteo marine 类问题类似，注意不要跨场景搬运结论）。
- 实测无 Referer、无频率限制问题（连打 5 次 `targetTc.json` 全部 200）。

## 5. 关于和风天气（本任务限定免 Key，此处仅记录实测现状）

- `https://devapi.qweather.com/v7/typhoon/now?location=101120101` → 实测 **404，响应体 0 字节**。

**因为 NMC 免 Key 路线已完全走通，本报告不给出和风的注册后端点方案**（任务限定「先找免 Key 的」）。若未来因 NMC 变更需要备份，再另行调研「账号专属 API Host + Key」方案。

需要说明的是：这次实测**不能**推广为「和风天气台风 API 不可用」。000 与 404 都可能由本机网络环境导致。按项目既有教训（和风公共域名 `Invalid Host` 曾被误判），这个结论**仅限于本机当前网络下不可达**，不代表服务本身不可用。

## 6. Open-Meteo 是否有台风端点

**实测：没有。**

```
GET https://api.open-meteo.com/v1/typhoon?latitude=25&longitude=121
→ 404, 43 字节: {"error":true,"reason":"Not Found"}
```

同一时刻、同一会话实测 `https://api.open-meteo.com/v1/forecast?latitude=25&longitude=121&current=temperature_2m` 返回 **200/220B 正常数据**，证明域名连通、鉴权正常，**是 `/v1/typhoon` 这个端点不存在**。

这与项目已有的 `marine-api` / `flood-api` 独立子域机制一致：Open-Meteo 的 API 是按子域白名单管理的，未纳入免费矩阵的端点不会存在。**台风路径不在 Open-Meteo 的产品线内。**

## 7. 给实施 worker 的注意事项清单

1. **JSONP 双层括号**：`(({"...}))`，需剥两层才能 `JSON.parse`。
2. **JSONP 回调名不固定**：`typhoon_jsons_list_default(...)`、`typhoon_jsons_view_3346168(...)`、`typhoon_jsons_list_2024(...)`，不要硬编码匹配，用「截断到首个 `(`」的通用策略。
3. **经度在纬度前面**：索引 4 = 经度，索引 5 = 纬度。写反会导致路径镜像到地球另一侧。
4. **数组定长但非严格类型**：索引 3/4 在不同年份是 number 或 string；索引 2 中文名带 `\n`；索引 10 可能是数组或字符串 `"list"`；索引 11 可能是 dict 或 `null`；索引 12 可能是数组或 `null`。
5. **强解码会崩**：建议按类型做安全取值（如 `as? [Double]` / `as? Int`），对 13 元素数组先判 count 再取下标。
6. **404 返回 HTML**：错误 id 时返回 HTML 而非 JSON，需先检查响应是否为 JSON 再解析。
7. **HTTPS 直接可用**：iOS ATS 无需配置例外。
8. **单位已确认**：气压 hPa、风速 m/s、移动速度 km/h、风圈半径 km、时间 UTC。**NMC 不需要单位换算**（JMA 的 `kt` 若接入则需换算）。
9. **注意时效延迟**：实测约 3 小时，UI 上不宜承诺「实时」，建议标注「数据来源：中央气象台，更新时间 HH:mm」。
